# 决策日志

本文件记录会影响产品方向、范围、架构、成本或交付方式的关键决策。

## 决策格式

- 编号
- 日期
- 状态：提议、接受、替代、废弃
- 决策
- 原因
- 影响

## D001：复盘作为核心，现场辅助后置

- 日期：2026-11-17
- 状态：接受
- 决策：首版以事后复盘为核心，模拟实时提示作为后续增强，实际面试现场辅助不作为核心。
- 原因：
  - 实时辅助涉及面试规则、隐私和伦理风险。
  - 单人两周同时完成实时链路和复盘闭环风险过高。
  - 复盘和重答更符合学习产品价值。
- 影响：
  - 首版重点建设问题卡、追问链、语音反思和重答。
  - 不建设隐藏式答案生成器。

## D002：首版用户聚焦学生项目答辩

- 日期：2026-11-17
- 状态：接受
- 决策：首版服务于应届生和在校生讲清楚自己的软件项目，而不是泛化到所有面试类型。
- 原因：
  - 开发者本人就是目标用户，便于获得真实样本。
  - 软件项目答辩问题类型稳定，便于设计分类和评估。
  - 后续可以自然扩展到研发岗位面试。
- 影响：
  - 首版问题分类围绕需求、技术选择、架构、贡献、测试、成本、风险和反思设计。
  - 不在首版同时支持销售、管理、艺术等场景。

## D003：单人开发和两周 MVP

- 日期：2026-11-17
- 状态：接受
- 决策：按单人开发约束规划，只交付一条完整主流程。
- 原因：
  - 没有并行开发人力。
  - 实时、多角色、社交和复杂后台会稀释核心价值。
- 影响：
  - 首版不建设实时 AI 评审和复杂后台。
  - 功能优先级以问题卡和复习闭环为准。

## D004：低成本优先的 AI 架构

- 日期：2026-11-17
- 状态：接受
- 决策：优先采用异步批处理、结构化存储、小模型分类、缓存和可选本地模型。
- 原因：
  - 产品需要长期使用，持续实时大模型调用成本过高。
  - 单场复盘只处理问题相关片段，可以显著降低 token。
- 影响：
  - 单场复盘目标控制在 3 到 5 次主要模型调用。
  - 后续需要记录 token、调用次数、延迟和单场成本。
  - 实际面试现场辅助不进入首版成本模型。

## D005：根目录中文，内部结构英文

- 日期：2026-11-17
- 状态：接受
- 决策：项目根目录使用 `X:\软件工程-ai面试`，代码目录和工程文件使用英文 ASCII。
- 原因：
  - 中文根目录便于用户识别和查找。
  - 内部英文目录更适合 Git、Docker、脚本和跨平台工具。
- 影响：
  - 文档正文使用中文。
  - 文件名称使用英文短横线格式。

## D006：文档先于代码

- 日期：2026-11-17
- 状态：接受
- 决策：在进入产品编码前，先完成项目章程、用户故事、验收标准、数据模型和风险评估。
- 原因：
  - 课程重视软件工程过程。
  - 单人开发需要避免边做边改导致范围失控。
- 影响：
  - Sprint 0 只处理过程、需求和技术基线。
  - 后续代码必须能追溯到用户故事和验收标准。

## D007：私有参考材料不直接公开

- 日期：2026-11-17
- 状态：接受
- 决策：老师平台截图等参考材料放入 `assets/references/private/`，默认不提交公开仓库。
- 原因：
  - 截图可能涉及第三方界面和未公开产品信息。
  - 开源仓库应避免无意传播未经授权的材料。
- 影响：
  - `.gitignore` 排除 `assets/references/private/`。
  - 如需公开，必须获得授权或重新绘制脱敏示意图。
