# 项目章程

- 文档版本：v0.1
- 创建日期：2026-11-17
- 项目状态：Sprint 0，待完成需求基线
- 项目负责人：用户本人
- 开发方式：单人开发

## 1. 项目背景

应届生和在校生经常需要向老师、评审、导师或面试官介绍自己的软件项目。真正暴露问题的通常不是准备好的汇报，而是评审提出的追问，例如：

- 为什么一定要用 AI？
- 你比较过哪些替代方案？
- 哪些部分是你自己做的？
- 数据从哪里来，怎么证明有效？
- 系统出错怎么办？
- 长期运行成本高不高？

这些问题在结束后很快被遗忘，用户也很难把一次问答转化成下一次可以使用的经验。

通用 AI 可以分析一次转写文本，但不会自动维护问题卡、追问链、证据缺口和复习状态。

## 2. 项目愿景

建设一个学生自己拥有的项目答辩复盘工具：

> 把一次问答变成一组可以理解、重答和长期复习的问题卡。

产品不替用户生成完美答案，而是帮助用户发现：

- 评审真正关注的考察点。
- 自己回答中缺失的证据和结构。
- 同类问题反复出现的原因。
- 下一次应该补什么材料和练习什么表达。

## 3. 第一目标用户

第一版用户画像：

- 应届生或在校生。
- 做过课程项目、比赛项目、毕业设计或个人软件项目。
- 需要在答辩、评审或研发岗位面试中介绍项目。
- 能提供真实或模拟问答录音、文字和项目材料。
- 愿意通过多次重答改善表达，而不是只寻找一次性答案。

开发者本人是第一号种子用户。

## 4. 核心场景

用户完成一次项目介绍或答辩后：

1. 导入录音、视频或文字记录。
2. 系统提取问题、回答和追问链。
3. 系统标注可能的考察点和回答缺口。
4. 用户通过语音补充反思。
5. 用户重新回答关键问题。
6. 系统比较前后变化并安排复习。

## 5. 项目范围

### 5.1 首版必须包含

- 复盘场次创建。
- 音频、视频或文字导入。
- 语音转写和基础说话人区分。
- 问题、回答和追问链提取。
- 问题意图和回答缺口分析。
- 问题卡编辑与保存。
- 语音反思记录。
- 重答和前后对比。
- 简单复习队列。
- 低成本模型调用和成本显示。
- Docker 部署和基础开源文档。

### 5.2 首版不包含

- 实时 AI 评审平台。
- 多角色评审大厅。
- 实际面试中的隐藏式答案生成。
- 复杂社交、排行榜和组织权限。
- 手机原生 App。
- 多语言支持。
- 完整企业级后台管理系统。

## 6. 关键约束

- 单人开发，时间约两周。
- 需要形成可运行系统，而不是只有原型图。
- 需要工程过程文档、测试记录、演示视频和答辩材料。
- 长期使用成本必须可控，不能依赖持续的大模型实时调用。
- 录音和项目资料涉及隐私，需要授权、删除和导出机制。
- 最终计划开源，文档和示例数据必须可公开。

## 7. 成功标准

### 7.1 产品闭环

- 用户能在 3 分钟内完成一次记录导入。
- 系统能提取问题、回答和至少一条追问链。
- 每个问题能形成结构化问题卡。
- 用户能完成一次语音反思和至少一次重答。
- 系统能展示重复问题或高频弱点。

### 7.2 工程质量

- 有明确的数据模型和接口说明。
- 关键流程有自动化测试或可复现测试步骤。
- 有部署说明和示例数据。
- 重要决策有记录，关键风险有应对方案。
- 单场复盘的模型调用次数和费用可统计。

### 7.3 过程质量

- 有项目章程、用户故事、验收标准和迭代记录。
- 每个 Sprint 有目标和可演示结果。
- 需求变更进入 backlog 或决策日志，而不是直接口头改代码。

## 8. 过程模型

采用轻量 Scrum 加迭代增量：

- Sprint 0：立项、用户、范围、风险和需求基线。
- Sprint 1：问题卡、导入、转写和结构化分析。
- Sprint 2：反思、重答、复习、部署和发布。
- 每日记录进展和阻塞。
- 每两天进行一次可运行演示。
- 重要架构和产品决策使用决策日志记录。
- 使用 Git 进行版本控制，后续采用短分支合并流程。

## 9. 质量属性

| 属性 | 目标 |
|---|---|
| 可解释性 | 意图和缺口判断尽量链接原文和时间点 |
| 隐私性 | 支持删除、导出和本地模型选择 |
| 成本可控 | 异步批处理、缓存、小模型优先 |
| 可移植性 | Docker 运行，避免绑定单一平台 |
| 可用性 | 主流程尽量在 3 分钟内完成 |
| 可维护性 | 问题卡和提示词版本化，避免不可追踪修改 |
| 开放性 | 数据结构、评估方法和示例数据可公开 |

## 10. 主要风险

- 只做转写和总结，容易被通用 AI 或老师平台覆盖。
- 单人两周范围过大，导致主流程不稳定。
- 实时辅助涉及面试规则、隐私和伦理风险。
- 模型调用成本超过长期使用承受范围。
- ASR 和意图分类错误导致用户不信任。
- 用户不愿意复盘，导致产品没有持续数据。
