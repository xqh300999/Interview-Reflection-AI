- 版本：v0.1
- 状态：待用户确认

## 3. P0 用户故事

### US-01：创建复盘场次

作为学生，我希望为一次项目答辩创建复盘场次，以便把记录和问题集中保存。

验收标准：

- 可以填写场次名称、日期和场景类型。
- 创建后进入场次详情页。
- 刷新后数据仍然存在。

### US-02：导入问答记录

作为学生，我希望导入文字、音频或视频，以便开始复盘。

验收标准：

- 支持粘贴文字。
- 支持上传一种音频格式。
- 上传后有明确的处理状态。
- 失败时显示可理解的错误信息。

### US-03：提取问题与追问

作为学生，我希望系统识别问题和追问链，以便快速定位需要复盘的内容。

验收标准：

- 每个问题显示原始文本和时间点。
- 追问与原问题关联。
- 用户可以手动修改问题和关联关系。

### US-04：生成问题卡

作为学生，我希望每个问题生成结构化问题卡，以便长期保存和复习。

验收标准：

- 问题卡包含原始问题、回答摘要、考察点和缺口。
- 考察点必须显示判断依据。
- 用户可以修改标签和掌握状态。

### US-05：记录语音反思

作为学生，我希望用语音回答复盘问题，以降低记录成本。

验收标准：

- 可以在问题卡上开始和停止录音。
- 录音可转写成文字。
- 反思内容与问题卡关联。
- 用户可以删除录音。

### US-06：重新回答问题

作为学生，我希望重新回答旧问题，以便检验是否真正掌握。

验收标准：

- 可以从问题卡进入重答模式。
- 新回答保存为独立记录。
- 页面可以对比第一次和第二次回答。
- 对比至少包含结论、证据和边界三个维度。

### US-07：查看复习任务

作为学生，我希望看到待复习和高频问题，以便知道下一次练什么。

验收标准：

- 首页显示待复习问题数量。
- 支持按掌握状态筛选。
- 显示至少一个跨场次重复主题。

### US-08：查看成本

作为用户，我希望知道一次复盘的模型调用和成本，以便决定是否长期使用。

验收标准：

- 显示模型调用次数。
- 显示 token 或估算费用。
- 显示处理耗时。
- 失败调用有记录。

## 4. Definition of Done

每个 P0 功能完成时必须满足：

- 有明确的用户故事和验收标准。
- 主流程可以从界面操作完成。
- 有错误状态和空状态。
- 有关键逻辑测试或可复现测试步骤。
- 有必要的文档更新。
- 不引入无法解释的外部依赖。
- 不泄露密钥、录音或项目隐私。

## 5. 首轮不做

- 实时 AI 评审。
- 多角色评审。
- 复杂组织后台。
- 公开展示和社交。
- 移动原生 App。
- 未经允许的实际面试隐藏式辅助。
