# 低保真页面原型 v0.1

- 版本：v0.1
- 日期：2026-11-17
- 目标：验证从文字导入到复盘、重答和复习的主流程
- 约束：先做桌面端 Web，不做移动原生 App，不追求视觉精修

## 1. 设计原则

- 问题卡是核心对象，不以整场会议纪要为中心。
- 每个 AI 结论都要能展开查看依据。
- AI 修正和用户编辑必须可区分。
- 页面优先展示“下一步做什么”，而不是堆统计数字。
- 低置信度、失败和空状态必须明确。
- 不做隐藏式实时答案提示。

## 2. 页面地图

| 页面 | 路由建议 | 目标 |
|---|---|---|
| 复盘首页 | `/` | 查看最近场次、待复习和重复弱点 |
| 新建复盘 | `/sessions/new` | 创建场次并导入文字或录音 |
| 场次详情 | `/sessions/:id` | 查看处理状态和问题组 |
| 转写校对 | `/sessions/:id/transcript` | 查看转写、低置信度和修正建议 |
| 问题卡详情 | `/questions/:id` | 查看问题、追问、缺口、反思和重答 |
| 复习中心 | `/review` | 查看待复习问题和练习任务 |

## 4. 新建复盘与导入

```text
┌──────────────────────────────────────────────────────────────┐
│ 新建复盘                                                     │
├──────────────────────────────────────────────────────────────┤
│ 场次名称 [AI Green 项目答辩复盘                          ]   │
│ 发生时间 [2026-11-15 20:15]  场景 [项目答辩 v]              │
│ 项目名称 [AI Green 智慧养老系统                           ]   │
├──────────────────────────────────────────────────────────────┤
│ [文字导入] [录音上传（后续）]                                │
├──────────────────────────────────────────────────────────────┤
│ 支持格式：                                            字数 0 │
│ 用户                                                         │
│ ...                                                          │
│                                                              │
│ AI 评审                                                      │
│ ...                                                          │
├──────────────────────────────────────────────────────────────┤
│ 预计模型调用：3 次    预计费用：待计算     [开始分析]        │
└──────────────────────────────────────────────────────────────┘
```

交互规则：

- 场次名称、时间和项目名称必填。
- 文字导入是首版可用入口。
- 录音上传可以先显示为后续能力，但不能做成不可解释的灰色按钮。
- 开始分析前显示预计调用次数。
- 空文本、格式错误和超长文本要有明确提示。

## 6. 转写校对

```text
┌──────────────────────────────────────────────────────────────┐
│ 转写校对                               待确认修正 5 条       │
├──────────────────────────────────────────────────────────────┤
│ 用户  00:01:20                                               │
│ 原文：我们使用 OoCircuit 消息代理。                          │
│ 建议：我们使用 MQTT 消息代理。                               │
│ 原因：疑似术语识别错误     置信度 0.72     [接受] [忽略]     │
├──────────────────────────────────────────────────────────────┤
│ AI 评审  00:01:27                                            │
│ 原文：你提到的消息代理是什么？                               │
│ [手动编辑]                                                   │
├──────────────────────────────────────────────────────────────┤
│ [保存修改] [重新分析]                                        │
└──────────────────────────────────────────────────────────────┘
```

交互规则：

- 原始文本和修正建议同时显示。
- 每条建议显示原因和置信度。
- 用户可以接受、忽略或手动编辑。
- 接受后的修改保留版本和来源。
- 重新分析前提示会覆盖哪些结构化结果。

## 7. 问题卡详情

```text
┌──────────────────────────────────────────────────────────────┐
│ Q04 服务端单点故障与兜底              高优先级   [待复习]    │
├──────────────────────────────────────────────────────────────┤
│ 原始问题                                                     │
│ 如果服务端全部无法处理，告警链路怎么兜底？                   │
│                                                              │
│ 追问链                                                       │
│ 1. 两层设备双报 → 2. 设备失联检测 → 3. 服务端单点故障        │
│                                                              │
│ 可能考察点                                                   │
│ [故障边界] [服务端容灾] [证据]                               │
│ 依据：评审在设备侧回答后继续追问“服务端层面”                 │
│                                                              │
│ 回答缺口                                                     │
│ - 主要在讲设备侧双报，没有回答服务端降级                     │
│ - 没有说明持久化、重试、补偿和人工接管                       │
│                                                              │
│ [录音反思] [重新回答] [标记已掌握]                           │
└──────────────────────────────────────────────────────────────┘
```

页面必须支持：

- 查看原始问题、追问链和原文依据。
- 查看意图、缺口、严重度和置信度。
- 播放原始录音片段，后续版本支持。
- 录制语音反思。
- 重新回答。
- 更新掌握状态。

## 8. 语音反思

```text
┌──────────────────────────────────────────────────────────────┐
│ 复盘这段回答                                                 │
├──────────────────────────────────────────────────────────────┤
│ 提示：你当时为什么没有直接回答“服务端层面”？                 │
│                                                              │
│ [开始录音]  00:00 / 02:00                                    │
│                                                              │
│ 转写草稿                                                     │
│ 我当时主要想到了设备双报……                                   │
├──────────────────────────────────────────────────────────────┤
│ 自评掌握程度：1  2  3  4  5                                  │
│ 下一步动作 [补充服务端降级和持久化方案                    ]   │
│ [保存反思]                                                   │
└──────────────────────────────────────────────────────────────┘
```

交互规则：

- 录音前显示提示问题。
- 录音过程显示时长和停止按钮。
- 转写失败时允许手动输入。
- 用户可以删除录音和转写。
- 自评只作为用户输入，不从声音推断。

## 9. 重答与对比

```text
┌──────────────────────────────────────────────────────────────┐
│ 重答：服务端单点故障与兜底                                   │
├──────────────────────────────────────────────────────────────┤
│ 第一次回答                                                   │
│ 设备双报，设备失联会通知专员……                               │
│                                                              │
│ 第二次回答                                                   │
│ [开始录音] 或 [输入文字]                                     │
├──────────────────────────────────────────────────────────────┤
│ 对比结果                                                     │
│ 结论：有改善 / 仍缺少明确结论                                │
│ 证据：新增持久化和重试说明                                   │
│ 边界：仍未说明主备切换时间和告警补偿窗口                     │
├──────────────────────────────────────────────────────────────┤
│ [保存重答] [继续练习]                                        │
└──────────────────────────────────────────────────────────────┘
```

对比至少包含：

- 结论是否更早出现。
- 证据是否更具体。
- 是否说明边界和失败条件。
- 是否说明个人贡献。
- 是否出现新的矛盾。

- 显示跨场次重复主题。

## 11. 状态设计

### 11.1 加载状态

- 上传中。
- 转写中。
- 问题提取中。
- 缺口分析中。
- 生成问题卡中。

每个阶段显示明确进度和可取消能力。

### 11.2 空状态

- 没有复盘场次。
- 没有待复习问题。
- 没有识别到明显缺口。
- 没有可用的成本数据。

### 11.3 错误状态

- 文本格式无法解析。
- ASR 失败。
- 模型超时。
- 预算不足。
- 网络中断。

错误信息必须说明：

- 发生了什么。
- 已完成哪些步骤。
- 如何重试。
- 是否产生费用。

## 12. 响应式要求

- 首版优先桌面端。
- 手机端至少可以查看问题卡和完成语音反思。
- 问题卡内容不能被固定高度裁切。
- 表格在小屏幕改为卡片列表。

## 13. 原型验收

- 能完成“新建场次 → 导入文字 → 查看问题卡 → 录音反思 → 重答 → 进入复习”的完整点击路径。
- 能看到至少一种低置信度修正建议。
- 能展开查看 AI 判断依据。
- 能看到一次模型调用和成本。
- 能明确区分原始转写、AI 修正和用户编辑。

## 14. 暂不设计

- 实时会议界面。
- 多角色评审大厅。
- 管理后台。
- 社交、排行榜和公开题库。
- 实际面试现场辅助。
